# Architecture

One npm package produces a browser-safe CommonJS plugin bundle. The public Obsidian module is provided by the host; React, React DOM, Zod Mini with English errors, original symbols and examples are bundled. Production output has no chunks, workers, native modules, runtime network calls or other required assets. Node 24 is a contributor build requirement only.

`src/core` owns the validated document, graph, integer geometry, bounded router, atomic edits, history and shared sessions. It has no React/Obsidian imports. `src/editor` translates pointer/keyboard intent into operations and renders SVG. `src/obsidian` adapts vault persistence, TextFileView and Markdown previews. `src/io` generates portable SVG/PNG. The development harness uses exactly the same core and editor, with explicit file downloads instead of vault storage.

DocumentSession clones at transaction commit and validates the complete resulting graph before publishing a new revision. Failed operations publish nothing. History stores at most 100 operations within an approximately 8 MiB budget, retaining the newest individual operation even if unusually large. Keyboard nudges within 400 ms coalesce; pointer movement remains a preview until pointer-up. Scene objects are memoized, pin hit candidates use a spatial index, viewport culling limits drawing, grid uses an SVG pattern, crossings are bucketed, and pointer updates run at most once per animation frame.

VaultSessions uses TFile identity, including across renames, to share one DocumentSession and SaveCoordinator between views and previews. All saves delegate to one serialized queue. Vault.process compares exact baseline contents before changing a file. This guards local stale writes and does not claim to be a distributed lock. The queue acknowledges only the written revision. External edits while clean replace the history baseline; dirty/conflicting versions suspend overwrite and preserve both. Write failure remains visible with retry/copy recovery. Deletion disables further writes to that file.

Recent normal saves and failures retain up to three recovery slots per session in the configured vault recovery folder (default `Circuit recovery/`). A reopened session starts a new recovery set, so old sets remain available until the user removes them. RecoveryStore serializes backup writes with folder migrations. The settings path is drafted first and applied explicitly with the inline Apply button, avoiding migrations on each keystroke. Migrations move only recognized recovery filenames, preserve unrelated files and destination collisions, and roll back moves if migration or settings persistence fails. Failed rollback reports both locations without deleting snapshots. Folder/ancestor rename events follow the actual location immediately; the preference and generated `00_README.md` are updated. A manually moved destination is reused, including after a disabled-plugin move. Generated instructions never overwrite an unrelated README. Older HTML ownership markers are recognized and removed when instructions refresh; current generated notes are recognized by their identifying introduction and both expected headings. Original circuit files remain separate from recovery storage. In-memory recent snapshots also remain available while the session lives. Close/quit/visibility hooks attempt a flush; only completed writes are durable. No OS force-kill guarantee is made.

React roots, subscriptions and window listeners are released on close. A public workspace layout-change event remounts UI resources if a view’s owning document changes during a pop-out move; its document/session/history remain shared. Camera/tool previews reset on that remount. Real host migration still requires qualification.

Optional recovery exclusion is isolated in RecoveryExclusions. Obsidian exposes no documented exclusion-list API in the installed 1.14.4 declarations; this feature guards the host's undocumented `getConfig`/`setConfig` methods and only changes `userIgnoreFilters`. It never edits app.json directly. The installed host's literal matcher treats entries as case-insensitive path prefixes; a trailing slash limits the managed rule to the recovery folder. Persisted ownership distinguishes plugin additions from existing user entries; duplicate ownership becomes ambiguous and is relinquished without removing either entry. User removal is remembered until explicit re-enabling or a different folder is chosen. Unreadable configuration or unavailable methods leave exclusions unchanged and produce a one-time fallback notice; backup writes and folder moves remain available. Dot-prefixed path segments receive no new exclusion. That check does not establish hidden-folder storage/Sync support.

Previews use the public `lecircuit` code-block processor and share sessions. They accept one path relative to the source note or vault root. Existing mounted previews retain TFile identity through a rename. After reopening a note whose code-fence path was not updated, a missing-reference message offers a circuit picker and explains how to repair the path. No broad note rewrite or private embed registry is used. An adjacent wiki link supports ordinary host rename tracking.

Version 1.0.0 includes a Build | Simulate studio with combinational digital simulation and electrical (analog) analysis. `useSimulation` (editor) chooses the engine from the parts, owns per-view electrical state (switches, probes, window) and acquires digital leases. `src/core/analog/` holds the MNA engine, model matching and engineering-unit parsing, with the canonical electrical allowlist in `src/components/definitions/analog.ts` ([ADR 003](adr/003-electrical-analysis.md)). DigitalSessions owns one revision-aware DigitalRuntime per DocumentSession, shared by visible panel consumers; an active run follows committed revisions automatically, and Logic inputs default to 0 at this layer. The panel hands its consumer to the Editor, which derives display-only SceneSignals (wire/node/pin values, input switches, probe lamps, display segments) for the Scene; signals never enter the document, exports or previews; reading previews never acquire an owner. Host-window task scheduling is abortable, hidden consumers pause, closing the last consumer releases the owner, and plugin unload disposes the pool. Pagehide/unload release consumers even when React cleanup is not delivered. CircuitFileView uses a temporary hidden consumer to hand over an open panel during a pop-out remount without resetting inputs. Runtime inputs/results stay ephemeral and never enter saves or history. The historical SimulationAdapter remains unused; the [digital architecture decision](adr/002-digital-feasibility.md) defines the actual contract and [simulation guide](simulation.md) defines the supported workflow. Unsupported devices reject the entire run. Simulation is not electrical safety certification; dated device qualification is in [the live UI record](evidence/simulation-live-ui/validation.md).

Overlap diagnostics use bounded spatial buckets and normalized collinear interval sweeps. Reports cap at 200 entries; extreme symbol bounds produce an explicit bounded-check diagnostic rather than expanding millions of cells.

The 0.1.1 workspace reads host theme variables directly, uses a categorized top-toolbar picker, and leaves the canvas full width until Properties is requested. The picker, gesture controls and canvas own distinct pointer sequences. Finish uses a committed canvas point, never the control's screen coordinates. Annotation transformations have preview-only gestures and atomic commit/undo; text scales proportionally by default.

Feedback uses ordinary external links to repository issue templates, activated explicitly by the user. Opening the dialog makes no network request and attaches no circuit/vault content. Zod Mini replaces the classic schema API so unused format validators and base64 codecs can be removed by the bundler; strict objects, numeric/string/array limits, annotation defaults, graph validation and schema version remain unchanged.

Simulation hardening distinguishes the original-file write phase from queued backup work, reserves the writer before observer notifications, and guards conflict resolution with epochs across reads/recovery. Deletion remains terminal even across reentrant notifications and late I/O; clean external loads acknowledge only their own committed revision, leaving observer edits unsaved until actually written. Shared runtime invalidation publishes pruned inputs and inactive intent together, and terminal disposal is set before notifying observers. Mobile simulation also consumes document pause/resume events: tested Android WebViews keep document.visibilityState visible after their Activity stops. Initial panel visibility is measured synchronously so an immediately visible control cannot lose a request before IntersectionObserver starts.
