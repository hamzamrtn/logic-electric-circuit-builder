# Release preparation

The local 0.1.4 ZIP and three individual assets are generated by `npm run package`. This workflow does not publish or submit anything. Publishing requires authenticated access to GitHub and the Obsidian Community directory. Release notes are in [releases/0.1.4.md](releases/0.1.4.md); the latest execution record is [evidence/release-0.1.4.md](evidence/release-0.1.4.md).

Before public release, complete the real-host/device checklist in validation.md, usability walkthroughs and competitor benchmarks. Fix failures, update evidence, confirm the owner’s identity/name/license choices, and repeat ID/extension/fence conflict checks. `docs/evidence/name-check.json` records the initial registry lookup; it cannot establish uniqueness of file extensions in unpublished plugins.

Build from a clean checkout with Node 24 and `npm ci`. Run lint, strict typecheck, core/property tests, Chromium/WebKit browser tests, production bundle audit and clean-package smoke. Validate examples and inspect the ZIP. Use a tag exactly matching the manifest’s numeric x.y.z version. Update versions.json if the minimum app version changes.

The prepared GitHub workflows run with read-only repository permissions, produce artifacts, and do not publish automatically. If adding release automation later, grant contents:write only to a trusted release job; never expose release credentials to untrusted PR code. A tag build must correspond to the reviewed source commit.

The official submission instructions checked on 2026-11-01 direct maintainers to community.obsidian.md. Create an appropriate public source repository, commit the manifest on its default branch, and create a matching GitHub release with `main.js`, `manifest.json`, `styles.css` attached individually. A ZIP is a convenience, not a replacement for those assets. Sign in to the community directory with the maintainer’s Obsidian account, connect GitHub and submit the repository. Address automated review feedback; a release does not guarantee acceptance.

Recheck the primary instructions immediately before submission:

- [Submit a plugin](https://docs.obsidian.md/plugins/releasing/submit-plugin)
- [Plugin submission requirements](https://docs.obsidian.md/community-directory/submission-requirements-for-plugins)
- [Developer policies](https://docs.obsidian.md/community-directory/developer-policies)
- [Public API definitions](https://github.com/obsidianmd/obsidian-api)
- [Mobile development](https://docs.obsidian.md/Plugins/Getting%20started/Mobile%20development)

No telemetry, self-updater, account, backend or runtime network dependency is included. Distribute the license/third-party notices with source; runtime license texts are included inside main.js. Document format changes separately from plugin rollback instructions.
